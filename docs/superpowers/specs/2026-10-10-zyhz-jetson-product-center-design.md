# 正阳恒卓 Jetson 产品中心设计规格

日期：2026-10-10  
状态：待用户审核  
项目目录：`D:\jetson\sites\zyhz-jetson-product-center`

## 1. 项目目标

为北京正阳恒卓科技有限公司建设一个面向客户的 Jetson 产品中心。网站主要服务产品浏览、选型、对比和采购咨询，安装、刷机、接口说明、下载和技术支持作为辅助内容。

成功标准：

- 客户能在首页快速理解公司覆盖的 Jetson 产品系列。
- 客户能根据产品形态、性能、内存、功耗、工业属性和应用场景筛选产品。
- 客户能横向比较最多四款产品，并进入独立产品详情页。
- 每个产品详情页同时提供采购入口和对应技术资料入口。
- 产品卡片、矩阵、详情和同系列对比的数据保持一致。
- 网站在桌面、平板和手机上均可阅读和操作。
- 所有真实产品能力均来自可核验资料，不编造参数、客户案例或认证。

## 2. 用户与任务优先级

### 2.1 主要用户

- 正在评估 Jetson 平台的企业客户、集成商和采购人员。
- 需要比较模组、开发套件和工业版本的研发负责人。

主要任务：浏览产品、理解差异、完成初步选型、联系客户经理获取报价。

### 2.2 次要用户

- 已购客户、现场工程师和开发人员。

次要任务：查找快速开始、刷机、JetPack 支持、接口说明、下载和常见问题。

## 4. 范围外事项

首版不实现：

- 用户账号、收藏同步或权限系统。
- 在线支付、库存锁定、正式订单或合同流程。
- 数据库、后台管理系统或在线编辑器。
- 未经用户提供或官方资料验证的价格、交期、客户案例和认证。
- 自动抓取 NVIDIA 官网并直接发布参数。
- 多语言版本。

## 5. 信息架构

顶部主导航：

1. 产品中心
2. 产品选型
3. 技术文档
4. 下载中心
5. 支持服务

主要路由：

- `/`：首页
- `/products/`：全部产品与系列入口
- `/products/{product-slug}/`：产品详情
- `/compare/`：产品矩阵、筛选与对比
- `/docs/`：技术文档总入口
- `/docs/{product-slug}/{document-slug}/`：产品技术文档
- `/downloads/`：下载中心
- `/support/`：技术支持与采购联系

产品不拆分为多个独立站点。所有系列、型号和文档使用统一导航、统一搜索与统一品牌样式。

## 6. 首页设计

采用已经确认的 C 方案精简版，视觉定位为“产品目录型”。

### 6.1 视觉原则

- 使用正阳恒卓现有 `ZYHZ + 正阳恒卓科技` Logo。
- 主色使用 Logo 的青蓝色，辅以白色、浅灰绿和深灰文字。
- 不使用大面积渐变、霓虹效果、重复宣传语或无意义动画。
- 使用清晰网格、细分隔线、留白和短文案体现工业产品的专业感。
- 产品图片承担真实展示作用，不作为装饰背景。

### 6.2 首页内容顺序

1. 品牌导航。
2. 简洁首屏：产品中心定位、产品矩阵入口、联系客户经理入口。
3. 四个产品系列入口。
4. 产品矩阵预览。
5. 典型应用场景入口。
6. 技术文档与下载入口。
7. 客户经理选型支持入口。
8. 公司和版权信息。

每个区块承担不同任务，不重复相同宣传内容。

## 7. 产品矩阵与比较

### 7.1 展示层级

- 首页展示精简系列矩阵。
- `/compare/` 展示完整产品矩阵与筛选器。
- 产品详情页只展示同系列比较。

### 7.2 矩阵方向

每款产品占一行，决策字段占列。避免将十二款产品全部横向排列。

默认列：

- 系列
- 产品名称
- 产品形态
- AI 性能及精度口径
- GPU 架构
- 内存
- 功耗
- 工作温度或工业属性
- 推荐用途
- 供货状态
- 详情、对比和询价操作

USB、UART、SPI 等详细接口不进入总矩阵，只在产品详情或同系列深度比较中展示。

### 7.3 筛选条件

- 产品系列
- 产品形态：开发套件、量产模组、工业模组
- 内存容量
- 功耗范围
- 工业级需求
- 应用场景
- 供货状态

### 7.4 比较规则

- 客户最多选择四款产品。
- 比较项按规格组展示，差异项可优先突出。
- 筛选与对比状态写入 URL 参数，使结果可以复制和分享。
- Thor 与 Orin 的性能值必须连同 FP4、FP8、INT8、稀疏性等口径展示。
- 不把不同计算精度的性能数字直接排序或合成为单一排名。

## 8. 产品详情页

详情页采用已确认的 AGX Orin 64GB 样板结构。

### 8.1 首屏产品区

- 面包屑导航
- 产品系列
- 中英文正式名称
- 产品形态
- 供货状态
- 一句话定位
- 真实产品主图
- 四项核心指标
- 获取报价
- 联系客户经理
- 下载规格书

网站不显示固定售价。采购入口统一导向客户经理。

### 8.2 产品亮点

每款产品显示四至六条经验证的差异化亮点。避免为每款产品复制完全相同的营销文案。

### 8.3 应用场景

按产品实际能力选取场景，包括但不限于：

- 机器人与具身智能
- 机器视觉
- 自动驾驶与无人设备
- 大模型本地部署
- 智慧交通
- 工业自动化
- 教学与研发

### 8.4 技术规格

规格按组展示：

- AI 性能
- GPU、Tensor Core、DLA、PVA
- CPU
- 内存与带宽
- 内置存储
- 视频编解码
- 摄像头能力
- PCIe、USB、以太网
- CAN、UART、SPI、I²C、GPIO
- 电源与功耗
- 机械尺寸与连接器
- 工作温度与生命周期
- JetPack、CUDA 和软件支持

开发套件、量产模组和工业模组使用不同的必要字段集合：

- 开发套件重点展示外部接口、装箱清单和快速开始。
- 量产模组重点展示连接器、尺寸、功耗、生命周期和载板适配。
- 工业模组额外展示 ECC、宽温、可靠性测试和长期供货。
- Thor 产品增加 FP4/FP8、MIG 和新一代高速互连字段。

### 8.5 型号比较

详情页提供同系列比较和推荐用途，帮助客户在相近型号间做升级、降配或工业版本选择。

### 8.6 技术资料

详情页展示文档卡片，不将全部操作说明堆入销售页面：

- 快速开始
- 安装说明
- 系统刷写
- JetPack 支持
- 接口使用
- 开发环境
- 常见问题
- 下载中心

### 8.7 采购信息

- NVIDIA 官方料号
- 正阳恒卓内部商品编号
- 包装清单
- 可选配件
- 供货状态
- 质保与支持说明
- 客户经理联系方式

首版客户经理姓名、电话、邮箱和二维码使用明确标注的模拟数据。正式发布前集中替换。

## 9. 技术文档体验

技术文档保留参考站点的左侧分级目录、页面目录、搜索、上一页和下一页导航，但使用正阳恒卓统一品牌样式。

每个产品的文档目录按实际内容裁剪，基础结构为：

1. 修订记录与安全说明
2. 产品规格
3. 快速开始
4. 系统刷写与 JetPack
5. 接口使用
6. 安装与散热
7. 配件
8. 常见问题
9. 下载与技术资源

文档内容以 Markdown 保存，构建时转换为静态 HTML。代码、命令、提示、警告和注意事项具有统一样式。

## 10. 下载中心

下载类型：

- 数据手册
- 用户手册
- 快速开始
- 系统镜像
- BSP 与驱动
- CAD 和机械资料

每个下载项包含产品、文件类型、版本、发布日期、文件大小和状态。未提供真实文件时显示“资料准备中”，按钮不可触发空链接。

## 11. 产品数据模型

所有产品展示使用同一份结构化产品数据。建议使用 JSON 数据文件，并在构建时进行校验。

产品核心字段：

```text
slug
series
nameZh
nameEn
productType
status
shortPositioning
heroImage
gallery
officialPartNumber
internalSku
coreMetrics[]
highlights[]
useCases[]
specGroups[]
performanceMetrics[]
softwareSupport[]
documents[]
downloads[]
packageContents[]
optionalAccessories[]
relatedProducts[]
sourceReferences[]
verifiedAt
```

AI 性能不使用单一裸数字，使用带上下文的结构：

```text
value
unit
precision
sparsity
powerMode
sourceReference
verifiedAt
```

必填字段缺失时构建失败。可选字段缺失时隐藏相应区块，不向客户展示 `TBD`、`null` 或空表格。

## 12. 内容来源与审核

来源优先级：

1. NVIDIA 官方产品页、数据表和开发者文档。
2. 正阳恒卓提供的内部 SKU、供货、服务与资料。
3. 经人工确认的公司原创说明。

每个关键参数保存来源链接和最后核验日期。产品图片优先使用公司自有素材或经授权的 NVIDIA 官方素材。网站保留 NVIDIA 和 Jetson 商标归属说明。

禁止发布：

- 未核验参数。
- 虚构价格、库存、交期、客户案例或认证。
- 将模组能力误写成开发套件或整机接口能力。
- 未注明精度口径的 AI 性能数字。

## 13. 技术架构

首版采用静态优先架构：

- 产品数据使用 JSON。
- 技术文档使用 Markdown。
- 构建脚本从数据和内容生成带独立路径的静态 HTML。
- 原生客户端 JavaScript 负责筛选、比较、文档搜索和交互反馈。
- CSS 使用统一设计令牌和响应式布局。
- 不依赖运行时数据库或服务端接口。

建议源码结构：

```text
assets/
content/docs/{product-slug}/
data/products.json
data/series.json
data/sources.json
templates/
scripts/build.mjs
src/styles/
src/client/
dist/
```

筛选和比较使用 URL 参数保存状态。文档搜索索引在构建时生成，并在浏览器本地查询。

## 14. 采购与支持交互

“获取报价”按钮携带当前产品名称进入支持页。首版不提交后台表单，展示模拟客户经理卡片和联系入口，避免产生无人接收的真实线索。

正式发布前替换：

- 客户经理姓名
- 电话
- 邮箱
- 微信或企业微信二维码
- 工作时间和响应承诺

按钮必须有加载、选中、复制成功或跳转反馈，避免设计确认页中“点击但看似无反应”的体验。

## 15. 异常与降级

- 缺少必填产品字段：阻止构建并列出产品和字段。
- 缺少可选规格：隐藏该行或区块。
- 下载文件缺失：显示“资料准备中”。
- 图片加载失败：显示产品名称和中性占位图。
- 搜索无结果：给出清除条件和浏览系列入口。
- 比较数量超过四款：阻止继续添加并提示先移除产品。
- 浏览器禁用 JavaScript：仍能浏览首页、产品详情和基础文档；筛选、比较和搜索提示需要 JavaScript。
- 外部来源链接失效：不影响客户页面渲染，但构建检查报告失效来源。

## 16. 响应式与无障碍

- 桌面端使用多列目录式布局。
- 平板端减少列数并保留筛选抽屉。
- 手机端将产品矩阵转换为产品卡片和逐项比较，避免横向滚动整张大表。
- 正文、表格和控件保持足够对比度。
- 所有交互支持键盘操作和明显焦点状态。
- 产品图、接口图和尺寸图提供替代文本。
- 不以颜色作为唯一状态信号。

## 17. 验收与测试

### 17.1 数据和构建

- 十二款产品均通过数据结构校验。
- 必填字段、重复 slug、错误关联产品和失效内部链接会导致检查失败。
- 页面不出现 `TBD`、`null`、空下载链接或模拟信息未标识的情况。
- 产品卡片、矩阵和详情页的核心参数一致。

### 17.2 功能

- 系列入口、筛选、重置和 URL 状态工作正常。
- 可添加、移除并比较最多四款产品。
- 产品详情、同系列推荐和技术文档链接正确。
- 文档搜索能返回产品和文档结果。
- 获取报价携带当前产品上下文进入支持页。
- 所有按钮提供可见反馈。

### 17.3 视觉与浏览器

- 验证桌面、平板和手机布局。
- 检查产品图片比例、规格表可读性和移动端比较体验。
- 检查键盘导航、焦点状态、标题层级和颜色对比。
- 检查主要浏览器中的导航、筛选、对比和下载状态。

## 18. 发布策略

首版通过 Sites 发布为私有预览，使用模拟客户经理信息和已验证产品资料。用户确认真实图片、联系方式和最终文案后，再创建正式客户版本并决定公开范围。

## 19. 后续扩展

不进入首版，但数据和路由设计允许后续增加：

- 正阳恒卓自研载板、整机和行业解决方案。
- 英文版本。
- PDF 数据表自动生成。
- 真实询价表单与线索系统。
- 公开价格或电商入口。
- 后台内容管理与版本审批。
